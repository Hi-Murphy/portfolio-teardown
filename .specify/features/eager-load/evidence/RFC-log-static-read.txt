5. Lighthouse simulate (Lantern) vs real time (reasoning, to be verified in AC1)
   - perf:lighthouse uses LH 13 defaults: formFactor mobile, throttlingMethod 'simulate'
     (tools/perf/src/lighthouse.ts L183-197). Lantern replays the observed trace as a dependency graph
     and multiplies each observed main-thread task by cpuSlowdownMultiplier = 4.
   - Timer/idle waits are causal edges, not durations, in that graph. So a mount that waits for
     load + idle in real time is packed next to hydration in simulated time ("coinciding at ≈ 4 s"),
     and a task contributes TBT iff 4 × (observed duration) > 50 ms, i.e. observed > 12.5 ms **on the
     measuring host**.
   - S11.6 T011 run 2: react-dom tasks of 198-212 ms simulated -> ≈ 50 ms observed on a slow-class
     runner. Locally (T010) eager TBT ≤ 1 ms -> every observed local task < 12.5 ms. A 4× gap between
     hosts whose benchmarkIndex differs only 1.85× points to host-specific work inside those tasks
     (candidate: software WebGL on the GPU-less runner; the local host uses ANGLE Metal, S11.5 C2).
     The runner's WebGL renderer string has never been recorded.

6. Ambient idle (S10 site-shell rfc.md Q2, spec.md L53)
   - "ambient idle" = the live view at rest: on-demand render, theme-live, no timed motion. The view
     stays `exploded`, never tweens, and runs no tour. A periodic motion would need a new xploder/motion
     token (S2 frozen).
