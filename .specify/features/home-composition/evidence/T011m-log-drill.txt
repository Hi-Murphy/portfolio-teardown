== Root cause ==
The failing transition is the browser Back step (popstate to `/`) after home -> project.
Before leaving home, keyboard focus on the project card had scrolled the page to
`scrollY=817`. The project document's footer had document top `1319.75`; while the
outgoing project document was still painted with the restored home scroll, that footer
appeared at `1319.75 - 817 = 502.75` in the viewport. The layout-shift entry named that
footer with `previousRect={x:0,y:502.75,width:1280,height:297.25}` and then
`currentRect={x:0,y:0,width:0,height:0}` as the route swapped and Next reset scroll.

The L6 footer-contact rule was ruled out: forcing the home footer contact block to keep
its geometry (`display:block; visibility:hidden`) left CLS at exactly 0.145672119140625.
The root cause is early scroll restoration against the outgoing document, not footer
height. `apps/web/components/site-footer.tsx` is unchanged.

Fix: `apps/web/components/hero/hero-scroll-memory.tsx` records the home scroll position
at internal-link activation and uses manual scroll restoration for that traversal. On the
Back traversal it lets `/` mount at the top, then restores the saved home position after
the home layout exists. Measured after: popstate reports `scrollY=0` on `/`; home then
receives `scrollTo(0,817)`, the footer returns to `y=1005`, and the drill records no
layout-shift entries.

== Orchestrator cross-check ==
Snap style removed (test-only build, not merged): drill-soft-nav-cls 0.0176572265625 (was 0.145672119140625 with snap).
The snap amplifies the shift but is not its only cause: the full-screen hero puts the project card deeper, so keyboard
focus scrolls the home page before the soft navigation, and Back restores that scroll while the outgoing project document
is still painted. S10 R5 deliberately counts hadRecentInput entries ("users can see this"), so the check stays as is and
the fix is the home-only scroll memory (manual restoration on traversal to /, restored after the home layout mounts;
other routes keep the browser default 'auto'). Trade-off accepted: on Back to /, the saved position is applied two
animation frames after mount instead of showing the outgoing page shifted.
