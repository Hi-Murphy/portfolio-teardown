## Hero zoom sample

Playwright sampled `canvas[data-xploder-camera-zoom]` once per animation frame during the hero
zoom-in phase at 1440×900, light theme. Three runs, 91 samples each:

```text
run  monotonic  final zoom   max per-step fraction
1    true       1.953125     0.327851
2    true       1.953125     0.331882
3    true       1.953125     0.334728
```

`1.953125 = 1.25³`. The step deltas are `0.25` (`1 -> 1.25`), `0.3125` (`1.25 -> 1.5625`) and
`0.390625` (`1.5625 -> 1.953125`). The worst frame was run 3 at `t ≈ 592 ms`:
`1.431004 -> 1.535607`, a raw delta of `0.104603` in the `1.25 -> 1.5625` step, i.e.
`0.104603 / 0.3125 = 0.334728`. That is below the 35 % threshold. The temporary sampler's older
`maxStepFraction` field divides by a fixed `0.25`; that denominator is only correct for the first
step and is not the value used above.

## Blocked check: `drill` home tab order (pre-existing)

The combined probe exits non-zero because four `drill` checks fail, all on the **home** tab
order or soft-nav CLS. The project-route checks in the same group pass:

```text
PASS drill-card-enter-url: expected "/projects/websocket-inspector" actual "/projects/websocket-inspector"
PASS drill-card-enter-viewer: expected true actual true
PASS drill-card-enter-h1: expected "Scarlet Inspector" actual "Scarlet Inspector"
PASS drill-soft-navigation: expected true actual {"project":true,"back":true}
PASS drill-back-card-reachable: expected true actual true
PASS drill-projects-one-activation: expected "/projects" actual "/projects"
PASS drill-card-hrefs-200: expected "every status 200" actual [{"href":"/projects/websocket-inspector","status":200}]
```

The failures:

```text
FAIL drill-tab-logical-order: expected [...,"footer:home","footer:email","footer:github","footer:linkedin","footer:top"] actual [...,"a:Email <email>","a:GitHub","a:LinkedIn","footer:home","footer:top"]
FAIL drill-shift-tab-reverses: expected [...,"footer:linkedin","footer:github","footer:email","footer:home",...] actual [...,"footer:home","a:LinkedIn","a:GitHub","a:Email <email>",...]
FAIL drill-no-trap: expected true actual {"stoppedAfterLast":true,"anchor":"footer:top","trap":false,"repeated":null}
FAIL drill-soft-nav-cls: expected 0 actual {"total":0.145672119140625,"entries":[{"hadRecentInput":true,...}]}
```

The cause is in `tools/perf/src/site-probe.ts`, not in T011l:

- `readDrillStructure` derives the expected footer keys with `footer a[href]`. On `/`,
  `apps/web/components/site-footer.tsx` hides its contact column with
  `[body:has([data-home-section=contact])_&]:hidden`, but those hidden anchors are still in the
  DOM and still in `querySelectorAll('footer a[href]')`.
- The actual tab walk correctly reaches the Contact section links
  (`apps/web/components/home/contact-section.tsx`: `a:Email`, `a:GitHub`, `a:LinkedIn`) and skips
  the hidden footer duplicates.
- The Contact section landed in T009; T011l changes only the hero opt-in and the engine JSON
  path. No T011l file touches tab order, the Contact section, the footer, or navigation.
- `drill-soft-nav-cls` is a separate false positive in the same group: the only CLS entry is
  `hadRecentInput: true` after the browser Back navigation.

Fixing this requires changing the site-probe harness (and/or the hidden footer anchors), which is
outside T011l's allowed file set. It is escalated rather than reworded or relaxed. The T011l
project-route requirement is covered by the seven passing project checks above and by the project
zoom sample.
