## 3. Findings

F1. Headless Chromium's display cadence is the ceiling. Frames are produced at the
    BeginFrame/vsync rate, measured here at 59.986 Hz. No content can produce more
    frames than the display cadence, so no estimator (harness or bias-free) can read
    >= 60.00 for any page, including the trivial calibration fixture.
F2. The harness's estimator (frames / windowMs) adds a further low bias of ~0.6 fps:
    the window start is a Performance timestamp taken before Tracing.start takes effect,
    so the first ~50 ms of each ~5050 ms window has no recorded frames (the window end
    is fine: last DrawFrame to trace end = 6.1 ms). This is an S3 tooling
    finding, not an engine property. It is not changed in S4 without a decision.
F3. The only ways to read >= 60.00 are to uncap the frame rate (e.g. Chromium flags
    disabling vsync / the frame-rate limit) or to change the estimator so it reports the
    nominal rate. Both would measure the instrument, not the engine. Not done.

Conclusion: under the literal reading, AC4 is blocked by construction, independent of
the engine. Escalated to Merlin (project layer) per the kickoff hard rules; the AC is not
reworded or relaxed by the orchestrator.
