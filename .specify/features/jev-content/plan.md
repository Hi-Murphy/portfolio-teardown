**Feature dir:** `.specify/features/jev-content/` · **Branch:** `task/s13-jev-content` · **Date:** 2026-11-14 · **Inputs:** `spec.md`, `rfc.md` (approved; §11 Gate 1: all defaults)

## Summary

jev-toolkit becomes the second entry of the existing content pipeline: one converter row, one generated module, one 9-line `defineProject` wrapper, one `PROJECTS` element and one tech-registry entry. Every consumer (route, cards, OG, metadata, sitemap, JSON-LD) is already generic over `PROJECTS`, so **no app UI, route or SEO code changes**.

The work is mostly proof. The order is fixed by kickoff Hard Rule 3: **fidelity test first**, then the route, then the cards, then OG/SEO, then the gate matrix. Tests and `tools/perf` probes that are hardcoded to websocket-inspector become project-generic from one guarded list. Two probe groups are added (`teardown` for AC1, `cards` for AC3), and `perf.yml` gains Lighthouse/weight steps for `/projects` and the new route.

**`packages/xploder` is not touched at all.** Neither are `apps/web/{app,components,seo}`.

## Guards (every task)

`.specify/features/jev-content/guards.sh` (created in T001) prints one line per guard and exits 1 on any failure. It uses the `guard NAME cmd` style of S11.

```sh
git diff --quiet 3b829d0 -- .specify/slices .specify/KICKOFF-S13.md .specify/content && echo FROZEN-OK
test -z "$(git log --oneline 3b829d0..HEAD -- .specify/slices .specify/KICKOFF-S13.md .specify/content)" && echo BRIEF-HISTORY-OK
git diff --quiet 3b829d0 -- packages/xploder && echo XPLODER-OK
for p in frozen-surface{,.s5,.s6,.s7,.s8}.paths; do git diff --quiet 3aee8fc -- $(sed 's#^#packages/xploder/#' packages/xploder/test/$p); done && echo SURFACES-S2S8-OK
git diff --quiet 3b829d0 -- apps/web/app apps/web/components apps/web/seo && echo UI-UNCHANGED-OK
git diff --quiet 3b829d0 -- tools/perf/src/a11y-axe.ts tools/perf/src/a11y-probe.ts tools/perf/src/engine-probe.ts tools/perf/src/panel-probe.ts tools/perf/src/presentation-snapshot.ts && echo S8-TOOLS-OK
git diff --quiet 3b829d0 -- .github/workflows/ci.yml .github/workflows/hero-eager.yml .github/workflows/eager-load.yml .github/workflows/eager-3d.yml && echo OTHER-CI-OK
# ALLOWED-PATHS-OK: every path changed since 3b829d0 is under the allowlist below (the "no special-casing" fence)
git diff --name-only 3b829d0 | grep -vE '^(apps/web/content/projects/|apps/web/content/tech-registry\.ts$|apps/web/scripts/convert-content\.ts$|apps/web/test/|tools/perf/|\.github/workflows/perf\.yml$|\.specify/features/jev-content/)' | (! grep -q .) && echo ALLOWED-PATHS-OK
pnpm --filter web content:convert --check && echo CONVERT-CHECK-OK
gitleaks git --no-banner --log-opts="3b829d0..HEAD" . && gitleaks dir --no-banner .specify/features/jev-content && echo GITLEAKS-OK
```

`UI-UNCHANGED-OK` and `ALLOWED-PATHS-OK` are how kickoff Hard Rule 4 (no special-casing) is enforced mechanically: if a task needs to touch app UI, route or SEO code, the guard fails and the task STOPs for escalation.

  1. outline (no-JS HTML of `projects/<slug>.html`): count layer headings, component items, flow items → equal to the source module counts;

  Screenshots of panel-open and tour-ended states go to `--out`.
- The exact selectors are taken from the S10/S11.9 probes and `site-axe` states, not invented. If a selector the group needs does not exist, the group uses what the existing probes use. It never adds a `data-*` attribute to app code (`UI-UNCHANGED-OK`).

| Choice | Why not simpler |

| A tooling list `PROJECT_SOURCES` next to the app's `PROJECTS` | tools/perf runs under Node type-stripping and cannot import `content/projects/index.ts` (runtime `xploder`, extensionless imports). A guard test makes the two lists provably equal to `.specify/content/`. |

| Copying S12's `main-diff.sh` into this feature dir with base `3b829d0` | It already implements the normalisation for "unchanged in behaviour" proofs. A copy keeps the S12 artifact frozen. |
